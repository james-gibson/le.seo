A link tree is the smallest marketing artifact that is still honest. It claims a reader, it claims
a purpose, and it puts the destinations in an order. Everything it leaves out is a decision
somebody made.

## What it is not

- **Not a directory.** A directory is complete and unordered; a tree is partial and ordered, on
  purpose. If a tree could be any list, it would be every list.
- **Not a homepage.** A homepage answers "what is this"; a tree answers "what should I open next,
  given who I am and what I came to do".
- **Not a sales funnel with the honesty filed off.** The order is stated, the values are in the
  address, and the same address shows the same list. A pitch that cannot be cited is a pitch that
  cannot be checked.

## The shape

```text
/v/<voice>/<goal>      a tree
/v/reader/try          one, concretely
```

Two values choose the set, and the set is printed in a fixed order: the least demanding front door
first, then by name. That ordering rule is the whole editorial policy — a reader who has not run
anything should not meet a toolchain first.

## What the page does when nothing matches

It falls back, and says so. If no destination answers both values, the tree falls back to the voice;
if the voice has nothing either, it falls back to the whole register. An empty pitch page is a worse
answer than a broad one, and a page that admits its basis is better than one that pretends the
match was exact.

## Built from other pickles

This seed publishes the tree as an isotope — [giardiniera](/isotope/giardiniera) — and it is built
the way the others are: <a href="https://james-gibson.github.io/le.gume/isotopes/silverskin/">silverskin</a>
for the site shape, cornichon for the recurring check that the links still resolve. A tree is a
site with a scheduled audit, not a static page and a hope.
